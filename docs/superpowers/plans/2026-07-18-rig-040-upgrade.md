# Rig 0.40 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade OPY from `rig-core 0.30` to `0.40`, isolate all Rig calls behind a Rust runtime boundary, and make provider token usage available through the existing Tauri/Effect contracts without changing current C4 behavior.

**Architecture:** Add `rig_runtime.rs` as the sole owner of OpenAI client construction, prompts, structured extraction, response metadata, and Rig error translation. Keep `ai_agent.rs` responsible for Tauri DTOs, key resolution, C4-specific prompts, sanitization, validation, and command adapters; it consumes typed runtime functions rather than importing Rig. Extend existing command responses and Effect schemas with a required, normalized usage envelope; persistence is intentionally deferred to the OPY-core plan.

**Tech Stack:** Rust 2021, Tauri 2, `rig-core = 0.40`, Tokio, Serde/Schemars, Effect Schema, Vitest, Bun, Cargo.

## Global Constraints

- Upgrade exactly from `rig-core = "0.30"` to `rig-core = "0.40"`; commit the corresponding root `Cargo.lock` update.
- Preserve current OpenAI-only execution, secret resolution, command names, C4 payload schemas, validation, and user-visible error prefixes.
- Task 1 deliberately leaves the existing `ai_agent.rs` Rig imports in place; Task 2 moves those calls behind `rig_runtime.rs`, after which it is the sole production Rig-import boundary.
- Do not add Anthropic, OpenRouter, streaming, `AgentRun`, hooks, Rig memory, tool loops, database migrations, or usage-budget UI in this slice.
- Use Rig `0.40` `PromptResponse::output()` and `PromptResponse::usage()` for ordinary prompts and `Extractor::extract_with_usage()` for structured extraction.
- Normalize all Rig `Usage` fields as non-negative `u64` values; a provider without usage reports emits zeros rather than omitting the envelope.
- Treat extractor usage as final-successful-attempt usage, not aggregate billing usage. Rig 0.40 discards usage from failed parse attempts, so a successful retry can under-report provider spend. Accept this upstream limitation for the narrow compatibility slice; preserve Rig extraction and the existing retry rather than hand-rolling either.
- Never return API-key material or raw provider request headers in a runtime error.
- Run focused Rust and TypeScript tests after each task; run format, Clippy, full Rust tests, frontend tests, lint, frontend build, and docs checks before closing the slice.

## Runtime Interface

`src-tauri/src/rig_runtime.rs` exposes these types and functions. `ai_agent.rs`
must not import any `rig::*` item after Task 2.

```rust
use schemars::JsonSchema;
use serde::{Deserialize, Serialize};

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct RigUsageMetadata {
    pub input_tokens: u64,
    pub output_tokens: u64,
    pub total_tokens: u64,
    pub cached_input_tokens: u64,
    pub cache_creation_input_tokens: u64,
    pub tool_use_prompt_tokens: u64,
    pub reasoning_tokens: u64,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct RigPromptOutput {
    pub message: String,
    pub usage: RigUsageMetadata,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct RigExtractionOutput<T> {
    pub data: T,
    pub usage: RigUsageMetadata,
}

#[derive(Debug, thiserror::Error)]
pub enum RigRuntimeError {
    #[error("Failed to initialize OpenAI client: provider client initialization failed")]
    Client,
    #[error("Rig prompt failed: provider request failed")]
    Prompt,
    #[error("Rig extraction failed: provider request failed")]
    Extraction,
}

pub async fn prompt_openai(
    api_key: &str,
    model: &str,
    preamble: &str,
    temperature: f64,
    max_tokens: u64,
    prompt: &str,
) -> Result<RigPromptOutput, RigRuntimeError>;

pub async fn extract_openai<T>(
    api_key: &str,
    model: &str,
    preamble: &str,
    max_tokens: u64,
    context: Option<&str>,
    retries: u64,
    prompt: &str,
) -> Result<RigExtractionOutput<T>, RigRuntimeError>
where
    T: JsonSchema + for<'de> Deserialize<'de> + Serialize + Send + Sync;
```

`RigUsageMetadata` is serialized in every existing response under the
camel-case field `usage`. Its TypeScript counterpart is:

```ts
export interface RigUsageMetadata {
  readonly inputTokens: number;
  readonly outputTokens: number;
  readonly totalTokens: number;
  readonly cachedInputTokens: number;
  readonly cacheCreationInputTokens: number;
}
```
